# SmartLoad Backend

FastAPI backend serving Ridge Regression models for building energy prediction. Part of an MSc dissertation project ("SmartLoad") that predicts building heating and cooling energy demand from early-stage architectural design parameters. This API is consumed by a separate React frontend (runs on `localhost:5173` in development).

## Tech Stack

- Python 3.10+
- FastAPI
- uvicorn
- scikit-learn (Ridge Regression, StandardScaler)
- shap (LinearExplainer)
- joblib (model persistence)
- numpy

## How to Run

```bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

API docs available at `http://localhost:8000/docs` once running.

## Model Details

- 8 input features (`Relative_Compactness`, `Surface_Area`, `Wall_Area`, `Roof_Area`, `Overall_Height`, `Orientation`, `Glazing_Area`, `Glazing_Dist`), 2 targets (`Heating_Load`, `Cooling_Load`).
- Ridge Regression models are trained on **scaled** features — the `StandardScaler` must always be applied before calling `.predict()`.
- SHAP values are computed with `shap.LinearExplainer` on the **scaled** input, and currently explain the heating-load model only.
- All model artifacts are loaded once at process startup (`app/predictor.py`, `app/explainer.py` module-level singletons) — never reloaded per-request.
- Feature order is canonical and defined in `app/config.py:FEATURE_NAMES`; every array passed to the scaler/models must follow this order.

## Endpoints

- `POST /predict` — accepts partial input (nullable fields default to training medians), returns HL/CL predictions, SHAP attributions, and a plain-language top-3 explanation.
- `POST /optimize` — accepts full input, sweeps each feature's valid candidate values to find heating-load-reducing changes, returns sorted recommendations.
- `GET /health` — liveness check.

## Notes for Future Changes

- If retraining produces new joblib artifacts, they must preserve the same feature order and be dropped into `trained_models/` with the same filenames — no code changes needed.
- `app/config.py` is the single source of truth for feature medians/ranges/candidates — update it there, not inline in route handlers.
